# 28 組固定矩陣的審查準則

使用同一份 prompts-17／program-validation-2 生成程式與 Antigravity gemini-3.8-flash／medium。沿用已接受的英文、日文四組新輸出，其餘 24 組各生成一次；不以重跑或挑選替代結果改善通過數。

生成、程式／來源／身份驗證、指定情境覆蓋及語意審查分開記錄。生成失敗的案例保留原錯誤、checkpoint 與已回報呼叫／用量，不進行內容審查；失敗呼叫未被記錄的部分標為未知。

Codex 對照完整來源、翻譯、逐句句意與脈絡、教學重點、可重用形式及所有新例句。這是 AI 編輯審查，不是教師／母語者認證、音訊驗證或學習效果測試。與四組試跑使用相同的接受標準：

- 翻譯、構造或例句有實質意義錯誤，阻擋接受。
- 將來源未確立的說話者、人物、性別、受詞、動機、因果、媒介或實際語調當成事實，阻擋接受。保留各語言來源本來已有的指涉；不能反過來移除明示資訊。
- 不明片段須在受影響欄位局部標明，不猜更正、含義或讀音；教學目標只引用可獨立成立的可靠周邊原文。未遵守時阻擋接受。
- 來源與例句分開：AI 例句可創作情境，但角色、動作、時間、問答與翻譯須一致，不能用例句細節填補原文。
- 所有指定來源與對話完整保留；正常對話的最後簡答若增加填充教學，視為固定情境覆蓋失敗。
- 冗長、重複、非必要術語與不影響已核對意義的泛化文案可列警告。錯誤的事實或不確定性不可只列警告。

一般情境特別核對來電與即將離開的時間關係、等待請求及簡短肯定回應。不確定情境特別核對聚會提問、引述者未明的轉述、話題轉換、不明詞義詢問及字幕不清楚的陳述。各語言的明示主語／性別依其實際固定輸入判定，不強制套用日文或英文的語法分析。

原始 runner 產物不修改，審查與最終接受判定另存。逐案問題需有 JSON 路徑、原文引句、嚴重程度及理由。用量只統計已保存的執行紀錄；reasoning 若包含於 output，不再相加。固定小樣本的通過比例不能推估整體語言正確率。
