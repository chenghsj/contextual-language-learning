## 方法與證據門檻

只複核初審未接受的八組；其餘二十組沿用初審結果，沒有重新核認，更沒有獨立認證。使用同一份不可變原始輸出，核對完整來源、被指摘欄位、實際 prompts-17 產品契約，並查閱有關代詞、處所義與義文構詞的辭典／教學資料。逐項依據、可成立的反面解讀、查閱日期與 URL 在 [decisions.json](./decisions.json)。

這是同一 Codex 審查者的事後、非盲複核，不是獨立第二意見。初審與此次複核都不能充當事先登記、已校準或可推估整體正確率的測試。外部資料能支持特定詞義或規則；不會自動認證嚴重程度、每個教材欄位或整體教學品質。

- **語言／內容退件**需要完整欄位的主張、可比對的矛盾或反例，以及實質影響的理由。局部句意是否容許詞典式提示，也必須依欄位定義判定。
- **產品契約退件**另標示依據：例如目前明文要求無說話者標籤的摘要不可連結回合。合理的自然語言解讀可能仍違反此契約，不能改稱為語言上不可能。
- **證據不足的既有指摘**可以撤回；存在更好的文案或更保守的改寫，本身不是原文錯誤的證據。
- **仍有實質爭議**使用 `needs_review`。這與 `warning` 不同，不能因為 error 數為零就自動通過。
- **測試覆蓋不足**仍標記未驗到該風險，不轉成語言錯誤，也不當作產品字幕遺失。

原始準則將一般情境概稱為「來電」過於籠統；是否為電話須依每個語言的實際輸入判斷，不能把英文電話情境強套到其他版本。此次新增法文媒介警告，並保留電話解讀可能合理的界線。

## 紀錄與離線核對

[初審接受紀錄](./initial-acceptance.json) 保留原始位元組；原本 `reviews/` 與 `review-rubric.md` 未修改。只有泰文、簡中、法文一般三份判斷有新版本，其餘審查由目前 acceptance.json 繼續引用。decisions.json 記錄初審檔案雜湊、八組唯一範圍及目前審查位置，核對工具也確認既有通過案例沒有被偷偷改判。

在儲存庫根目錄執行：

```sh
node --import tsx docs/quality/matrix-2026-10-19-prompts17/verify.mts
pnpm exec tsc -p docs/quality/matrix-2026-10-19-prompts17/tsconfig.json --noEmit
```
