## 自動品質流程

新的實驗 compact 任務凍結 `compact-source-review-1`。在原本的跨場景等價整理請求中，同時檢查所有選中來源、翻譯、語境、教學點及例句；不增加一個每次都執行的獨立品質請求。

回應包含等價群組、具來源證據的 issues 與限定 patches。檢查特別涵蓋人名猜譯、確定性擴大、錯誤引用／角色推斷、文法條件、例句自然度與情境、讀音及原 ruby。

- 沒有語義錯誤時，保存檢查證據後完成任務。
- 有可修補錯誤時，在同一交易中套用一輪修補，保留原稿，再進行一次語義複查。
- 有未修補錯誤、禁止修改的問題，或複查仍有錯誤時，停止正式完成；保留 checkpoint 與可讀部分教材。再次 Resume 不會自動重付同一輪檢查或無限修補。
- JSON／結構格式問題仍沿用既有的有限格式修補與容量重試；語義複查本身不會啟動第二輪語義修正。

修補只可替換既有的標題、翻譯、語境／意思、教學說明、chunk 意思，以及單一完整 AI 例句。例句須再次通過目標、結構、註音與數量驗證。來源文字、來源單元、ID、spans、來源表達、類別、pattern、item kind 及數量都不能被改寫。需要修改上述保護欄位的錯誤會阻止完成，不能以刪除教材迴避。

每個 issue 須引用實際場景／上下文的合法 UTF-16 範圍，patch 須對應已報告的 error，不能藉 style warning 改寫教材。原稿、修補、複查與每場景的 qualityReports 均持久化；草稿與來源設定 hash 綁定檢查證據。取消時收到的完整回應先保存，重啟只處理未完成狀態。

舊 compact checkpoint 沒有新版本標記，續跑仍使用原先契約；不會被自動升級而增加模型工作。正式 legacy 流程不受此次實驗契約變更影響。

## 選材精簡

新版本以候選的 firstCueId／lastCueId 表示完整連續區間，仍提供共用表內的每條原文及全部 ruby。移除重複的 dialogueCueIds 清單及選材不需要的 utf16Length；沒有縮短候選場景、刪除字幕或改變模型／明確推理強度。

用上一輪相同候選池離線建構：提示從 33437 減為 26477 字元，減少 6960（約 20.8%）。這是輸入字元數改善，**不是新的模型耗時測量，也不代表首場景 60–90 秒已達標**。排程並行上限及原有來源順序保持既有行為。
