## 實驗策略

只有在明確指定實驗 compact 流程及 `compactAutomaticReasoning: "low"`，且原請求未指定推理強度時，候選搜尋才使用 low。場景選擇、教學與等價整理保留已解析的原強度（本次 medium）。任何明確的使用者強度都不降級。

策略版本 `light-candidates-1` 及候選／選擇實際強度寫入 execution；各階段預算依該強度計算。續跑沿用 checkpoint，即使新的 JobManager 沒有實驗旗標，也不會變更已凍結的設定。每次模型呼叫另記錄實際強度，收到不一致的回應時保留付費歷史並停止。

正式預設仍為 legacy。原教材、既有任務、已安裝 Host 與擴充功能沒有被覆寫或重載。

## 語義審查與最後一次修補

逐項比對四段來源、所有翻譯、15 個教學點、13 組例句及保留的讀音。第一場景有未經來源支持的人名漢字／譯名、把「要注意人物」擴大成「危險人物」，以及新增引用或強迫語意等問題。最後一次模型工作只可替換已審查的 16 個翻譯／說明字串；修補另花 48.08 秒。

修補後的衍生教材通過結構及來源品質複查。程式逐欄比較證明只有該 16 個字串變更，來源文字、ID、spans、日文例句、註音與原 execution 完全一致。衍生檔案不覆寫原始生成任務；修補的 paid-call 證據獨立保存在 report。此審查由代理依來源完成，不代表母語者、實際音訊或影片播放驗收。

保留的來源讀音包含 cue-374 字幕自帶的「外出＝そとで」，沒有以字典猜讀覆寫原 ruby。原生成有 24 筆可選註音省略／對齊診斷，均保留；沒有將缺失的可選註音描述為已補齊。等價整理回傳空群組，逐項檢查也未發現必須合併的跨場景同義重複。

修補與審查紀錄位於 `work/compact-full-quality-repair-20261103/`。4 分 20 秒冷啟動加 48 秒修補已約 5 分 8 秒，且不含人工介入的等待與審查時間，不能聲稱品質驗收後的端到端 3–5 分鐘已達標。

## 格式修正與剩餘界線

本輪觀察到 JSON 中的 `reading` 屬性未加雙引號。新增僅在字串外、物件鍵位置引用該已知鍵名的有限正規化；仍須完整 JSON parse 及原結構／來源驗證，絕不 eval、擷取片段或改動文字值。原始失敗回應的離線重播已通過完整場景結構驗證。這個修正可避免同類錯誤再付費修補，沒有據此虛構更短的全片耗時。

另補強嚴格 JSON 與人名／確定性提示。這兩項在本次冷啟動程序載入後才加入，沒有進行新的模型冷啟動驗證；本次 15／15 次已全部使用，後續沒有追加請求。先前兩輪的模型工作紀錄維持不變。

**正式預設仍未切換，也未安裝或重載。** 原因是首場景 60–90 秒尚未達標；品質修補仍是獨立審查步驟，尚未驗證修正後完整自動流程。後續應先整合來源語義品質檢查、驗證更新後冷啟動，以及實機閱讀／取消／續跑，再決定正式啟用。
