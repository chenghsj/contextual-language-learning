## 結論

方向可行，但目前還不是可以直接照做的完整規格。核心應改為：**以選定對話的完整原句為教學單位，依程度與啟用類別辨識值得學的重點；可重用表達只是其中一種，延伸例句只附於適合移用的項目。**

不能只把「最多兩個」刪掉。候選篩選、教學資料模型、數量預算、解析呈現和新生成驗證都仍以表達為入口。下方分開保留「需求吻合度」及「架構／契約一致性」兩個審查軸；同一根因可能同時影響兩軸，不代表不同程式缺陷。

## 需求吻合度審查

1. **已確認衝突：不能只取消教學階段的 1～2 個限制。** 使用者要求「直接找該程度可以學的重點」，但候選已先依可重用表達選材，而且只選 1～2 個；後續只解析含表達的原句，其他對話明確排除。應將候選目標改為「有上下文、適合程度的對話及其教學價值」，選定後檢視全部原句的學習重點。[候選與篩選](../apps/local-host/src/generation/scene-prompts.ts#L50)、[解析範圍](../apps/local-host/src/generation/scene-prompts.ts#L138)

2. **已確認衝突：研究草案仍以 expression 為必要入口。** 現存研究中的 `For each selected expression` 草案只補解說品質，沒有改選材單位；`focusIndexes` 也仍將原句解析綁在表達上。該草案是在討論取消兩個限制之前撰寫，不能當成新方向的完整設計。[舊品質補強草案](./content-settings-prompt-research.md#可先採用的-prompt-補強草案)、[原句解析契約](./inline-sentence-analysis.md#資料與生成契約)

3. **規劃風險：程度應決定優先順序與解說負擔，不能成為考綱過濾器。** 「該程度可以學」不代表原句含超程度形式就略去必要理解。應允許簡短補充必要前提，同時避免逐字講解所有基礎項目。現有「尺度只是選材與負擔指引」值得保留；沒有個人已知詞資料，不能斷言使用者已學會某項。[程度與深度](../apps/local-host/src/generation/language-strategies.ts#L68)、[尺度限制](../apps/local-host/src/generation/language-strategies.ts#L91)

4. **待決策：Off 與 Detailed 是否影響選材。** 關閉文法後，不宜仍只因文法教學價值而優先選某場景。Detailed 應增加解說深度，不要求增加重點數；啟用類別如何影響候選排序，需要明文定義。全部關閉仍保留情境、原文、翻譯和基本意思。[目前偏好注入](../apps/local-host/src/generation/language-strategies.ts#L80)、[偏好契約](./inline-sentence-analysis.md#使用方式)

5. **規劃風險：按字串去重會漏掉不同用法。** 同一字串在不同情境可能有新的學習價值；目前全片選材按正規化字串刪除，沒有區分義項、功能或語域。新規劃應去除重複解說，保留不同用法。也不必因此實作通用語義搜尋：已生成重點的教學去重，與原片字串出現搜尋是不同責任。[現有去重](../apps/local-host/src/generation/scene-pipeline.ts#L151)、[字串出現搜尋](../packages/core/src/expression-occurrences.ts#L32)

6. **範圍要寫明：完整檢視的是選定對話。** 建議繼續讓內容長度控制選取素材量；完整檢視選定對話的原句，不等於找出整部影片所有可學項目，也不強迫每句產生解說。例句只附於真正可移用的項目，數量要和總輸出負擔一起規劃。[場景數](../apps/local-host/src/generation/scene-prompts.ts#L71)、[現有例句要求](../apps/local-host/src/generation/scene-prompts.ts#L121)

## 架構／契約一致性審查

1. **硬衝突：學習重點仍被當成逐字表達。** `focusExpressions`、`focusItems`、`sentenceAnalyses` 限制最多兩項；`focusIndexes` 只允許 0／1，每個 focus 又必須有 1～3 組例句。文法關係、指涉和省略不一定能表示為一個連續原文字串。應先區分原句解析／學習重點與可移用表達／框架，例句只屬於後者。[候選 schema](../packages/core/src/schema.ts#L140)、[焦點與場景 schema](../packages/core/src/schema.ts#L184)、[解析 schema](../packages/core/src/explanations.ts#L45)

2. **硬衝突：選材及驗證仍會裁掉新重點。** 現行流程以 `sceneCount * 2` 作總預算，每場景只保留兩個表達；教學只解析這些表達所在句。選材、全片篩選、教學與驗證需要一起改，否則新規劃會被舊裁切規則抵消。[選材預算](../apps/local-host/src/generation/scene-pipeline.ts#L151)、[教學預算](../apps/local-host/src/generation/scene-pipeline.ts#L449)、[最終限制](../apps/local-host/src/generation/scene-pipeline.ts#L547)

3. **待決策：新增資料的相容政策。** 現行解析是 V5 可選補充，缺失時讀者從舊 focus 建立替代內容。若新解析成為教材主體，就不能把新生成失敗沿用成「無效直接丟棄仍成功」。需定義舊教材可讀、新生成最低交付、checkpoint 版本處理，保留原字幕 ID、文字、時間與 UTF-16 定位，抽象框架另存。文件是否升版取決於資料相容設計，不能只因改 prompt 就武斷決定。[解析降級](../packages/core/src/sentence-analysis.ts#L58)、[續跑檢查](../apps/local-host/src/jobs/manager.ts#L181)、[目前相容契約](./inline-sentence-analysis.md#保存與相容)

4. **待決策：可變數量的資源界線。** 不固定兩個不等於無上限生成；需要每場景輸出預算、例句適用範圍、超量拆批及修復單位，避免詳細解說、讀音與例句相乘而截斷。目前標準模式的預估只計算候選階段輸入，不能當整份教材成本；新的拆批規則須納入凍結的執行版本和計畫。[輸入估算](../apps/local-host/src/generation/input-estimate.ts#L28)、[執行快照](../apps/local-host/src/jobs/manager.ts#L101)、[計畫續跑檢查](../apps/local-host/src/jobs/manager.ts#L201)

上述硬衝突針對「把新規劃直接套到現有契約」；不代表現行功能違反當時的舊規格。本次沒有提出無關的程式風格或一般性重構要求。

## 建議定稿的整體流程

保留三個模型階段，來源定位、驗證、保存和修復由流程處理；不預設為每個學習重點新增一次模型呼叫。

| 階段     | 輸入／任務                                                                         | 交付與邊界                                                                                     |
| -------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 候選探索 | 依目標語言、程度與啟用類別，找有上下文、能獨立理解且有教學價值的完整對話           | 回傳原字幕引用與簡短教學價值；不要求先有固定片語，也不在全片候選階段寫完整教材                 |
| 整段篩選 | 按使用者內容長度，平衡情境完整、程度負擔、實用性、學習面向與重複內容               | 凍結選定對話及完整原句來源；不以「表達數 × 場景數」當教學配額                                  |
| 原句教學 | 檢視選定對話中的完整原句，產生基本意思及相關學習重點，再整理可移用表達／框架與例句 | 數量由實際內容決定；重點可為字詞、結構、指涉、省略或語用。沒有相關重點的句子仍可只提供基本內容 |

不能以「不限重點數」承諾無限教材。當輸出超過模型預算，按完整原句拆批，帶足理解所需的原始上下文；保留完成部分、明確處理未完成部分，不默默丟掉低排序重點後宣稱全部完成。候選分段也應有跨字幕斷點的完整性規則，避免把完整原句切斷。

## 建議定稿的教學規則

- **程度：** 決定選材優先順序、所需前提、用詞和術語負擔；保留原句，必要時用簡單說明支援超出程度的內容，不改寫來源成簡單句冒充原文。
- **關閉：** 不生成該類深入補充；原文、翻譯、基本意思及情境保留。基本意思可以釐清指涉，但不要藉基本欄位偷偷塞入整段已停用的文法課。
- **一般：** 說明相關原句在此處如何理解、必要成分如何組合。
- **詳細：** 在相同程度補有用的關係、差異與使用限制；不因此湊更多點、換更難原句或提高例句數。
- **分類：** 六類是解說角度，一個知識點可能涉及多個角度；同一意思只完整解釋一次，不把六類當每句必填清單。
- **理解片段與可移用項目：** 前者幫助理解此句，後者可以在適用條件下移用。不要強迫所有學習點都有固定字串、可替換槽位或延伸例句。
- **例句：** 每個適合延伸的項目沿用設定的 1～3 組；自然示範同一核心用法，符合程度及語域，翻譯相符。沒有可移用項目的原句可以沒有例句。形式變化與抽象框架另標，不能冒充原片字面內容。
- **去重：** 合併同用法的重複解說，保留來源位置；不同義項／功能可獨立教學。字串搜尋只代表其他出現，不保證同義，也不擴大成新的語義搜尋功能。
- **證據：** 不編造來源對話、角色心理、文化背景或時間；AI 例句允許創作並明確標示。只有字幕文字時，讀音是可靠的一般提示，不能確定演員實際重音或語調。
- **全關閉：** 基本情境閱讀仍可生成，不因沒有可用補充類別而硬造學習點。

## 資料與閱讀介面的必要決策

建議先定義概念與責任，再決定具體欄位名稱，不以重新命名 `focusItems` 代替設計：

1. **完整原句**有穩定 ID 和實際字幕引用，承載基本意思、理解片段與原句解說。
2. **學習重點**可以引用整句、部分範圍或多處相關來源；不必是連續片語。解說分類與可重用性是不同維度。
3. **可移用項目**在需要時附於重點，保留原文形式、可選抽象框架與例句；沒有可移用項目不影響其他重點成立。
4. **引用關係**應能穩定經過排序、去重及拆批；不要把讀者呈現永遠綁在最多兩個的位置索引上。
5. **閱讀介面**以原句解析為入口，能呈現沒有固定片語的文法／語用重點；例句與其他出現入口只在適用時顯示。點選仍讀取已生成內容，除非另外明確規劃按需生成。

新生成使用明確的輸出驗證和品質修復；舊 V5 教材維持相容讀取，不憑空補內容。若採新增可選欄位，必須確認保存、匯出、備份、還原和所有讀者都能保留／使用；若改成不相容主體，需明確文件版本與資料政策。兩者擇一應在實作前定稿。prompt、workflow 及相關語言策略變更需反映執行版本，既有任務不得混用新舊計畫續跑。

## 自訂 Markdown 的範圍

此規劃主體是標準教材。自訂 Markdown 繼續尊重使用者 prompt；不能因共用「內容設定」頁就宣稱繼承同一份學習重點資料契約。內建教學範本可另補來源、程度和發音證據規則，但不在本次順便全面改造自訂生成。[獨立自訂 request](../apps/extension/src/lib/generation-request.ts#L45)、[自訂生成](../apps/local-host/src/generation/custom-pipeline.ts#L61)

## 驗收應檢查的外部行為

| 案例                               | 預期結果                                                   |

| 語句簡單、沒有有用的詳細延伸       | 詳細可以與一般接近，不灌水                                 |

## 建議實作順序

1. 定稿原句、學習重點、可移用項目的資料責任，以及範圍、偏好和相容規則。
2. 同步調整三階段 prompt、來源／數量驗證、輸出示例及版本；保留舊教材讀取。
3. 接上閱讀、保存、匯出及備份，補新生成的完整性檢查、按句拆批與局部修復。
4. 用固定素材和模型版本審閱真實產物，再比較一般／詳細、不同程度、停用類別及其他語言。樣本評估與安裝版／影片播放驗收分開報告。

需求軸共 6 項（其中 2 項是既有草案與新方向的明確衝突）；架構軸共 4 項（其中 2 項是直接套用現行契約的硬衝突）。各軸最主要問題分別是前段仍以表達篩掉可學內容，以及資料仍要求所有重點都是帶例句的逐字表達。本次只新增審查文件，沒有修改功能或進行真實模型生成。
