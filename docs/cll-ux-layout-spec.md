## 1. 產品目標與原則

### 1.1 目標

- 將現有「影片與字幕 → 分析範圍 → 內容類型 → 設定與 Prompt → 建立內容」5 步驟簡化為 **3 步驟**，不刪除既有功能。
- 保留已習慣的流程，同時提供「沿用上次設定」快速建立入口。
- 讓使用者在 Side Panel 內完成字幕取得、選取範圍、AI 設定、生成與閱讀；需要更大畫面時可展開 Web 版本。
- 設定與活動中心不再讓使用者迷失在獨立頁面；改用**從右側進入、最大 640px 的 Sheet**。
- 生成為背景任務，Side Panel 關閉後的執行能力須由可靠的背景執行架構提供，而非假設網頁仍在執行。
- 支援由使用者自行連接的 AI Provider、登入帳號或 API Key；介面不將任何訂閱制服務誤判成「免費 API」。

### 1.2 不變原則

1. **建立頁的資料不因開啟 Sheet、切換步驟或關閉 Side Panel 而消失。**
2. **選項依情境揭露**：只有選「自訂時間」才顯示時間軸；只有展開 Provider 才顯示連線操作。
3. **一個畫面一個主要操作**：Step 1/2 是「下一步」，Step 3 是「建立內容」。
4. **避免中斷**：生成完成不自動跳走；失敗不堵塞整條佇列。
5. **清楚說明不可用功能**：無字幕時間戳則不能承諾跳轉；Native Host 不可用則不能承諾持續背景執行。
6. **可讀性優先**：Side Panel 會被使用者自由調寬；內容需有限寬、可響應變化。

### 3.2 導航行為

- App Header 的設定圖示：開啟 `settings` Sheet，初始顯示「設定首頁」。
- App Header 的活動圖示：開啟 `activity` Sheet，顯示任務列表；如有執行中任務可優先顯示。
- `Sheet → 子頁`：**在同一張 Sheet 裡切換內容**，禁止 Sheet 再開 Sheet。
- 子頁左上角 `←`：返回設定首頁或其父層；`X`：關閉 Sheet 並返回先前工作畫面。
- 設定首頁頂部只有「設定」標題及 `X`；不再使用容易誤讀的 `← 設定`。
- 活動中心同理，右上角 `X` 關閉；如有任務詳情，可用 `← 活動中心` 返回列表。
- 字幕預覽為建立流程內的**獨立內部畫面**；返回 Step 1 時恢復表單與捲動位置。
- 點擊生成完成通知：直接進入對應教材，未完成任務不觸發閱讀導覽。

## 4. Side Panel 響應式外框

### 4.1 基本原則

Side Panel 寬度由 Chrome 使用者拖曳改變。**所有容器都以實際可用寬度響應**，而非假設固定 360px 或 417px；高度也可能很小。

- App 根容器：`width: 100%; min-width: 0; height: 100dvh;`。
- 內容區建議 `max-width: 640px; margin-inline: auto;`，窄版左右 `16px` padding，寬版可 `24px`。
- App Header 可以滿寬，表單與設定內容收斂到中心容器。
- 設定／活動 Sheet：`width: min(100%, 640px)`；在 **Side Panel 自己的 viewport** 中由右側滑入。窄版全部覆蓋、寬版保留左側背景遮罩。
- Chrome 自帶的 Side Panel 標題列不屬擴充功能 DOM，無法用 Sheet 覆蓋；Sheet 可覆蓋的是**擴充功能自己的內容區**。
- 不依靠 `sm:` / `md:` 判斷內容排版；必要時在主要內容容器使用 **CSS Container Queries**。
- 行動裝置使用的瀏覽器／Web 版本要分開測試，不直接假設 Chrome Side Panel 在手機可用。

### 4.2 參考寬度行為（設計建議，非硬性平台 breakpoint）

| 側欄寬度     | 建議布局                                                        |
| ------------ | --------------------------------------------------------------- |
| 約 320–399px | 單欄；Stepper 短標題；時間輸入框若不足則上下排列；Sheet 滿寬    |
| 約 400–639px | 單欄；開始／結束時間可同列；Sheet 滿寬                          |
| 約 640–899px | 表單置中限寬；Sheet 最多 640px，右側滑入                        |
| 900px 以上   | 主要表單仍不超過 640px；長清單或預覽可在更寬的 Web 視圖使用雙欄 |

### 4.3 應用畫面骨架

```text
┌────── Chrome 原生 Side Panel Header（不能修改） ──────┐
│ Contextual Language Learning                   [X] │
├────────────────────────────────────────────────────┤
│ [Logo] Contextual Language Learning   [活動] [設定] │ ← App Header
│ [建立內容] [內容庫]                               │ ← Primary Nav
│ ────────────────────────────────────────────────   │
│  ① 影片       ② 設定       ③ 建立                  │ ← Stepper
│ ┌───────────────────────────────────────────────┐  │
│ │                                               │  │
│ │                 可捲動表單內容                 │  │
│ │                                               │  │
│ └───────────────────────────────────────────────┘  │
│ ────────────────────────────────────────────────   │
│ [上一步]                             [下一步 →]    │ ← 固定 Footer
└────────────────────────────────────────────────────┘
```

> 截圖中 Chrome 原生標題與 App Header 都顯示產品名稱。建議 App Header 保留品牌與主要操作，但控制高度，避免在窄視窗中重複堆疊標題。這屬進一步 UI 精簡建議，非 28 題決策本身。

### 4.4 捲動區與固定 Footer

- Header、Primary Nav、Stepper、Footer 不跟表單捲走（Stepper 如高度空間過小，可採精簡單行版）。
- **只有主要內容容器滾動**；不要讓整個 Side Panel、表單卡片及 Accordion 同時出現三層垂直捲軸。
- Footer 需要實際佔用布局高度，不能只 `position: fixed` 擋住最後一個表單欄位。
- 虛擬化字幕清單是例外：有自己的專用捲動容器，但不與建立流程表單同時滾動。
- Sheet 需獨立滾動，其背景視圖在 Sheet 開啟期間不可互動；關閉恢復既有 scroll position。

### 5.2 分析範圍 Select 與自訂時間

| 選項             | 行為                        | 顯示額外控制                       |
| ---------------- | --------------------------- | ---------------------------------- |
| 完整影片（預設） | 範圍涵蓋可用字幕／影片時間  | 無                                 |
| 前半部           | 預設影片總時長的前 50% 範圍 | 顯示範圍摘要                       |
| 後半部           | 預設影片總時長的後 50% 範圍 | 顯示範圍摘要                       |
| 自訂範圍         | 使用者指定開始／結束        | **雙端點 Range Slider + 時間輸入** |

```text
選擇「自訂範圍」後
┌────────────────────────────────────┐
│ 分析範圍                           │
│ [自訂範圍                       ▾] │
│                                    │
│ 開始                 結束          │
│ [00:12:30.000]      [00:28:45.000] │
│ [使用目前位置]       [使用目前位置] │
│                                    │
│ 0:00   ●════════════════●  1:44:27│
│                                    │
│ [跳至開始]                         │
│ 目前選取：16 分 15 秒              │
└────────────────────────────────────┘
```

- 使用**單條雙端點**選取時間範圍，取代原本上下兩條難以分辨的滑桿。
- 始終保證 `0 <= start < end <= duration`，並提供明確的驗證訊息。
- 修改 Slider 時更新時間欄位；輸入時間也同步 Slider；避免捲動或拖曳時與播放控制互相競爭。
- `使用目前位置` 只在原始影片分頁已成功連接時可操作；未連接則停用並說明原因。
- 自動長影片分段是**後台處理方式**，與使用者選擇的「分析範圍」是兩個不同概念；不額外把它變成新的設定步驟。
- 若影片沒有可信 duration，停用「前半部／後半部」並引導補足時長或手動輸入可用區間；不可用猜測的時長切片。

### 5.3 字幕擷取與備援

正常狀態：自動擷取已存在的字幕，選擇語言，顯示段落數。

```text
字幕取得失敗
┌────────────────────────────────────┐
│ 無法自動取得字幕                   │
│ 請確認影片字幕已開啟，或嘗試重試。 │
│                                    │
│ [重新偵測字幕]                     │
│                                    │
│ 其他字幕來源                  ▾    │
│   ├─ 貼上字幕文字                 │
│   ├─ 匯入 .srt                    │
│   └─ 匯入 .vtt                    │
└────────────────────────────────────┘
```

- SRT / VTT 需解析文字與 timestamp，匯入前給出格式錯誤資訊；純文字貼上可能沒有時間戳。
- **無時間戳資料**仍可供某些生成任務使用，但不能聲稱支援精準跳轉、循環或分段對齊。
- 手動字幕與擷取字幕採相同內部資料格式，但記錄不同來源 `source`。
- 重取字幕時不要直接覆寫已編輯版本，依第 6 節衝突流程處理。

```text
│ 變更會自動儲存至本機               │
└────────────────────────────────────┘
```

### 6.3 字幕編輯規則

- 每筆字幕有穩定 ID、`startMs`、`endMs`、`text`、`source` 與編輯紀錄。
- **保留不可變的原始快照 + 可修改工作版本**。編輯不可回寫 YouTube / Netflix 的平台字幕。
- 文字與時間先保留在修改視窗的草稿；按「完成」才更新工作版本並 debounce 寫入本機，顯示「儲存中／已儲存／儲存失敗」。取消、關閉或 Esc 捨棄本次草稿。
- 時間使用 `MM:SS.s`，超過一小時才顯示小時；未調整的欄位保留原始毫秒精度。直接輸入仍接受最多三位小數；按鈕每次微調 0.1 秒，方向鍵同樣微調，Shift + 方向鍵調整 1 秒。
- YouTube 的字幕清單、修改視窗與試聽共用有效時間：預設結尾取下一段有效字幕的原始開始時間，沒有下一段時保留原始結尾。手動時間獨立保存並優先套用；只改文字不會建立時間設定。「重設時間」移除該筆手動設定，回到自動範圍，按完成後生效。
- 連接影片時可暫停並讀取目前位置作為開始／結束，或試聽尚未儲存的範圍一次。停止、關閉視窗或離開字幕預覽會清除本次試聽；未連接時播放控制停用，仍可修改文字與時間。
- 避免 `start >= end`、負時間、超過影片可用時長。相鄰字幕時間重疊可警示，但**不強行假設所有字幕都不可重疊**（多說話者情況）。
- 「復原」只影響工作版本；還原原始字幕前需說明將失去目前工作版本變更並要求確認。
- 再次擷取字幕時：出現 `保留既有編輯 / 使用新擷取字幕 / 取消`；建議先備份舊工作版本再替換，避免不可逆遺失。
- 生成任務開始時擷取字幕版本**快照**，避免編輯進行中改變背景任務輸入。
- 搜尋與捲動使用虛擬化清單（例如 TanStack Virtual）；點擊時間跳轉只在連接影片且時間有效時啟用。

### 8.2 Step 3 可直接更換模型

- Provider → 帳號 → 模型 → 推理強度為依賴選單；切換 Provider 後重新檢查可用帳號與模型。

- 若 Google Drive 未連接或失去權限，顯示可理解的處理方式；不應在未告知的情況下改存其他位置。

## 9. 快速建立與 Stepper

### 9.1 快速建立

- Step 1 可用且字幕已準備好時出現 `使用上次設定，快速建立`。

- 「上次設定」建議以模式／語言維度記憶常用模板，但**實際影片草稿優先**，以免覆蓋既有影片特定設定。

### 9.2 Stepper 規則

- 主要流程標示 `1 影片`、`2 設定`、`3 建立`，窄版不使用容易換行的長文字。
- **已完成**：可點，直接前往；**目前步驟**：高亮；**未完成步驟**：不可點。
- 從 Step 3 點「修改影片／修改內容設定」可以直接回對應步驟。
- 編輯前面步驟若造成依賴資料失效（例如字幕換語言、時間超出時長、切內容模式），將該部分標記為需重新確認。
- `上一步` 和 `下一步` 的可用狀態由實際驗證決定；不要只用索引自增而忽略資料完整性。

### 9.3 固定底部 Footer

```text
┌────────────────────────────────────┐
│ [表單可捲動內容]                   │
```

- Step 1：左側可放「快速建立」的次要入口，右側「下一步」。
- Step 2：`上一步 / 下一步`。

- Footer 使用背景與上方邊界（border 或輕微陰影）區隔內容；不可擋住最後一個欄位。
- 生成 API 呼叫送出中，提交按鈕 loading 並禁止重複提交；**加入佇列成功後**才視為建立成功。

## 11. AI Provider Accordion 與多帳號

### 11.1 未連接 Provider：原地展開

```text
┌────────────────────────────────────┐
│ 可連接                             │
│                                    │
│ ┌────────────────────────────────┐ │

│                                    │

└────────────────────────────────────┘
```

- 點擊某 Provider 時**在該列下面**開啟，不在清單最底部出現控制區。
- 一次只展開一個 Provider；重複點擊同一 Provider 收合；其他項目自動收合。

- 依 Provider 能力顯示 OAuth／API Key／其他登入方式；不能假設每個 Provider 都同時支援這兩種。
- 不以橘／紅色邊框當作「展開」狀態；使用輕微背景或中性邊框，警告色保留錯誤。

### 11.2 已連接 Provider：多帳號管理

```text
┌────────────────────────────────────┐
│ Antigravity                    ▴   │
│ 已連接 · 使用中                    │
│ ────────────────────────────────── │
│ 帳號                               │
│                                    │

│   OAuth · 已連接                   │
│   [管理] [重新登入]                │
│                                    │
│ ○ 帳號 B               [切換使用]  │
│   OAuth · 已連接                   │
│   [管理] [中斷連接]                │
│                                    │
│ [+ 新增帳號]                       │
└────────────────────────────────────┘
```

- `Provider -> Account[] -> activeAccountId`，允許存在多筆帳號。
- 不同 Provider 的 `accountId` 必須和 provider 一起作為複合識別，不可只用 email 當 key。
- 切換帳號會重新取得或篩選可用模型，必要時清空不再有效的模型選擇。
- 新增 OAuth 帳號時應避免覆蓋既有授權；**如果 Pi/CLI 目前僅能使用單一授權狀態，UI 應明確禁用多帳號操作或顯示限制**，不能假裝切換成功。
- `重新登入` 與 `中斷連接` 需明確指定某帳號；中斷連線需二次確認。
- Provider 曾經連接但已失效，狀態應是「需重新授權」，而不應只顯示「已連接」。

```text
│ [前往取得 API Key ↗]               │
│                                    │
│ [驗證並連接]                       │
│                                    │
│ 金鑰由本機安全機制管理；            │

```

- API Key 僅透過使用者同意的本機安全機制保存；避免存入 `localStorage`、一般 `chrome.storage.sync` 或 UI log。
- 已存的 API Key 不應可被 UI 反向讀出完整明文；使用 replace／revoke 操作管理。
- 若憑證存放系統 Keychain / Credential Manager，由 Native Host 提供不返回完整密鑰的操作介面。
- 安全說明需涵蓋 Native Host、權限與網路傳送目的，避免以「儲存本機」一詞泛稱已經安全。

## 13. 背景任務與失敗處理

### 13.1 佇列架構

```text
 Side Panel UI                       持久化 Job Store
 [建立內容] ──建立任務快照───┐         ▲        │
                              ▼         │        ▼
                         [任務佇列管理器]───> [單一 Worker]
                              ▲                     │
                    訂閱狀態／取消／重試               ▼
                              │              [字幕分段規劃]
                              │                     │
                       [活動中心 Sheet]             ▼
                              │              [分段分析 1…N]
                              │                     │
                              │                     ▼
                              │              [整合生成結果]
                              │                     │
                              └────進度事件─────────┤
                                                    ▼
                                                [儲存文件]
                                                    │
                                                [完成通知]
```

### 13.2 明確區分 Side Panel 與背景執行

- Chrome Manifest V3 的 service worker 可能被停止；**不能只依賴 Side Panel React component 或 service worker 記憶體維持數分鐘的長任務**。
- 若要求 Side Panel 關閉後仍持續跑 Pi/CLI 分析，需讓 **Native Host／本機任務管理程序**實際擁有排程、持久化與執行生命週期；擴充功能重新開啟時查詢任務狀態。
- 一般 Native Messaging 連線並不自動等於永久常駐、跨平台背景服務；必須驗證 Host 安裝與程序存活、重開機恢復方式及失去連線時的真實行為。
- 無 Native Host 或背景執行條件不成立時，應明確顯示「關閉面板後可能暫停」，而不是提供無法兌現的承諾。
- 任務、字幕片段 checkpoint、最終檔案寫入狀態都要持久化，確保 UI 重新開啟不會造成整個執行流程丟失。

### 13.3 依序執行（已定）

- 任務可多筆提交，**同時間只執行一筆**。其餘為 `queued`。
- 佇列順序預設 FIFO；若新增插隊需求需另行定義，v1 不自行新增。
- 佇列開始執行前再次驗證必需授權與 Host 能力。
- 一筆失敗後依重試策略處理；確定失敗才釋放 Worker 給下一筆。
- 任務取消與重新送出必須具備 idempotency key 或原子狀態轉移，避免重複執行。

### 13.4 自動長影片分段

1. 只對 Step 1 指定的字幕時間區間分析。
2. 根據**可用模型的實際輸入限制與合理輸出預算**選擇目標段落大小。
3. 優先在句子／情境邊界切分，保留必要的上下文（overlap），但避免重複輸出同一場景。
4. 每片段獨立記錄 `segmentId`、時間區間、輸入 hash、模型及狀態。
5. 成功片段保存 checkpoint；失敗重試只處理尚未成功的片段。
6. 所有有效片段完成後，執行整合階段，輸出一份教材；若內容過長則整合也可分層進行。
7. 計費／用量統計包含分段請求與整合請求；若發生重試須分開紀錄。

### 13.5 重試決策

| 錯誤類別                  | 自動重試                  | 行為                                                               |
| ------------------------- | ------------------------- | ------------------------------------------------------------------ |
| 暫時性網路錯誤            | 最多 2 次                 | 指數退避 + jitter；有重試建議時間則優先遵守                        |
| 429 / rate limit          | 視回應可安全重試最多 2 次 | 尊重 `Retry-After`，不要高頻重送                                   |
| 臨時 5xx                  | 最多 2 次                 | 重試後仍失敗則顯示錯誤                                             |
| 授權失效 / API Key 無效   | 否                        | 導向正確帳號重新授權                                               |
| 額度不足 / 付款問題       | 否                        | 清楚說明，讓使用者處理                                             |
| 請求格式／Prompt 驗證錯誤 | 否                        | 顯示修正資料的方法                                                 |
| Host 未安裝／離線         | 否（可進待處理）          | 提供 Host 安裝、重新連接入口                                       |
| 請求可能已扣款但結果未知  | **不立即盲目重試**        | 查詢 job/request status、利用 provider 的 idempotency 能力或先提示 |

- **「最多 2 次」指原請求之外的額外重試次數**（至多總共 3 次嘗試），並記錄累計次數。
- 某片段最終失敗後將當前任務標記 failed／blocked；佇列繼續下個任務。
- 手動重試優先恢復失敗步驟／片段；若模型或字幕已修改，應啟動新的相容性檢查與新任務快照。
- 所有重試均不可保證零成本；在 UI 以實際用量為準。

## 14. 完成通知與教材開啟

### 14.1 完成後的行為

- 活動項目更新為 `completed`，包含教材 ID 與實際儲存位置。
- 若使用者仍在建立內容或其他頁面，**不自動跳頁**。
- 通知允許時，可送出桌面／瀏覽器通知；使用者也可從 Header 活動中心看到完成狀態。
- 點擊通知或活動任務，預設**在 Side Panel 打開教材閱讀頁**；提供「在 Web 中開啟」。
- 若目前未允許通知，仍需保證活動中心顯示結果；通知權限不影響生成任務成功與否。

### 14.2 找回對應影片

```text
開啟教材
   │
   ├─ 搜尋相同平台 + videoId 的已開啟分頁
   │    ├─ 有匹配 → 嘗試建立播放控制連線
   │    └─ 多個匹配 → 優先目前使用中的匹配；必要時提示選擇
   │
   └─ 無匹配 → 顯示 [開啟原始影片]

沒連線仍可閱讀教材，但跳轉、循環等播放功能暫時停用。
```

- 影片 ID 應自平台 URL 正規化，避免不同追蹤參數產生重複分頁。
- **不要在找不到影片時直接新增分頁**（選擇為「提示使用者」）。
- Netflix 等受保護平台的播放控制依實際可用能力，不承諾所有環境都能嵌入 iframe 或操控 DRM 播放。
- Web 閱讀頁如要控制原分頁，須經由 Extension 通訊（例如 messaging）；不能假設一般網站可直接操作另一個分頁。

### 14.3 內容類型與閱讀

| 產出類型      | 儲存資料                       | 閱讀方式                                          |
| ------------- | ------------------------------ | ------------------------------------------------- |
| 標準教材      | 結構化教材 + 時間戳 + metadata | 場景、重點句、單句與整組播放                      |
| 自訂 Markdown | Markdown 文件 + metadata       | Markdown 閱讀器，只有存在合法時間戳的元素提供跳轉 |

- 為兼容未來複習，文件 ID、影片 metadata、語言及字幕版本均保留在 metadata 中。
- 兩種模式可以共用一個內容庫入口，但**分類、資料 schema、生成 Prompt 與 renderer 必須分開**。
- 內容庫按來源識別（`sourceKey`）合併標準教材與自訂 Markdown，同一文件的本機與 Drive 副本只計一次，群組按最新內容排序。名稱相同但來源不同時不可合併。
- 多份內容的群組以可展開列呈現，標題最多兩行，完整名稱保留於按鈕文字與 `title`，份數獨立放在右側；展開後使用分隔線排列內容。搜尋命中的群組預設展開，語言與類型篩選共用同一份清單。
- 卡片省略重複的來源標題及資料格式版本；學習位置與瀏覽比例共用一列，開啟／繼續學習操作靠右，進度條在下方。自訂內容不顯示虛構的學習進度。
- 舊版雲端自訂內容若缺少來源識別，先獨立顯示，還原至新版 Host 後由已保存的來源資料計算識別；不可按標題猜測關聯。
- 標準教材閱讀佔滿 Side Panel；隱藏品牌列、主導航及獨立內容庫返回列，將返回操作整合至教材標頭。場景名稱只放在場景選擇器，教材內文獨立捲動，標頭及播放器固定。
- 播放器使用三排：目前控制的場景／句子與序號、置中的上一段／播放／下一段、兩端附時間的進度條。內部三排共用最大 720px 寬度並水平置中，外層背景仍佔滿畫面，窄版使用可用寬度。循環位於播放控制旁，速度與更多選項靠右；左右欄等寬，播放鍵位置不受速度文字影響。窄版縮小速度欄及控制間距，保持三排。前後按鈕依目前控制對象切換，「播放完整對話」放在原始對話標題旁，可直接切回場景並播放。活動、設定及 Web 開啟由更多選項提供，無影片教材保留這些入口。
- 點原句文字或句子列可展開／收合解析；逐句閱讀時切換到另一句會收合前一組。語塊點擊獨立切換解說重點，播放及朗讀不改變解析開合。不另設「解析」按鈕；收合時也顯示群組邊界、句子範圍（如 `01–02`）與箭頭，範圍列提供鍵盤開合及 `aria-expanded` 狀態；解析內容點擊不收合，語塊只在展開後提供切換；解析底部不重複放置收合按鈕。
- 原始對話工具列提供「全部展開／收合」，只控制目前場景的解析；全部展開後仍可獨立開合每一組。跨字幕解析共用一個區塊與開關，放在最後一句下方。群組間距一致，展開時原句與解析共用淡背景，解析縮排對齊原句、不以分隔線切斷關聯；主要意思加重，教學說明使用正文色，空的說明區塊不佔留白。
- 原句、解析與例句共用文字欄的左邊界，語塊不額外加水平內距；編號與播放操作對齊第一行正文，而非注音。逐句播放留在各句右側，整組朗讀放在群組範圍列，涵蓋該組所有原句，每條原字幕之間加入約 0.3 秒停頓，保留字幕內部的換行與標點；沒有解析群組的句子保留同列朗讀。群組朗讀與逐句播放使用同一個 32px 右側欄位，圖示中心共用垂直對齊線；單句的朗讀操作放在播放鍵左側，播放鍵不左右漂移。工具列捲動時固定在內容頂部；一般高度視窗的展開群組固定精簡範圍列，短視窗不固定範圍列，避免遮住閱讀區。
- 長說明按完整句子分段，強調已有的表達與標題關鍵詞，不刪減教學內容；更多解說、AI 例句及其他出現位置一次只展開一項。

## 15. 儲存、草稿、重複檢查

### 15.1 依影片獨立草稿

- `draftKey = platform + canonicalVideoId`，不同影片各自保存；若無影片 ID，使用穩定的手動來源識別碼。
- 同一影片可保留標準教材及自訂 Markdown 的各自設定；草稿載入時不把一方覆蓋另一方。
- 草稿內容：影片 URL、標題、字幕語言與字幕版本、範圍、目前步驟、各 Tab 設定、Prompt、選擇模型與帳號、Step 3 目的地、最後更新時間。
- 修改時 debounce 寫入；關閉 Side Panel 後再開啟，先從本機載入再同步連接狀態。
- 恢復時重新驗證依賴：影片時長、字幕版本、Provider 可用性、授權有效性、模型是否存在。
- 草稿與已完成的生成文件**不同資料實體**；一筆生成任務啟動後用 immutable snapshot，後續草稿修改不污染任務。

### 15.2 儲存分層（建議實作）

| 資料                                      | 建議位置                            | 備註                                |
| ----------------------------------------- | ----------------------------------- | ----------------------------------- |
| 主題、語言、預設模型等小型偏好            | `chrome.storage.local`              | 非機密設定                          |
| 長字幕、編輯工作版本、草稿、教材 metadata | IndexedDB（例如 Dexie）             | 支援索引、版本與較大資料            |
| 待執行任務、checkpoint、Host 執行狀態     | Native Host 持久化資料庫／任務儲存  | 必須配合背景執行機制設計            |
| API Key／OAuth 敏感憑證                   | 系統安全儲存 + 必要的 Host 存取控制 | 不存放於一般 frontend state persist |
| 生成文件                                  | 使用者指定本機資料夾／Google Drive  | 依權限、路徑與同步策略              |

### 15.3 重複檢查指紋建議

```ts
// 用於解釋要比對的邏輯，不是直接 hash 整個物件字串。
type GenerationFingerprintInput = {
  platform: "youtube" | "netflix" | "other";
  canonicalVideoId: string;
  subtitleLanguage: string;
  subtitleContentHash: string;
  startMs: number;
  endMs: number;
  contentMode: "standard" | "markdown";
  effectiveSettingsHash: string;
  promptHash: string;
  providerId: string;
  modelId: string;
  reasoningEffort?: string;
  pipelineVersion: string;
};
```

- hash 前必須以 deterministic serialization 正規化輸入，避免物件 key 順序造成偽差異。
- 比對**已完成結果及排隊／進行中的任務**，避免相同工作重複支付。
- 同影片不同範圍、不同行語言、不同 Prompt／模型應可建立不同結果；可以另顯示「此影片有其他版本」，但不作完全重複。
- 「重新生成」建立獨立 revision，不刪除舊文件。

## 16. 元件規格與 Tailwind 範例

### 16.1 shadcn/ui 選型

| 功能               | shadcn/ui / 其他元件                  | 建議                                 |

### 16.5 響應式細節

- 文字與 Select 值使用 `min-w-0`、`truncate`（必要時 tooltip），避免模型長名稱撐爆 Side Panel。
- 兩欄時間輸入使用 container query；低於可用寬度時變成上下排列。
- 主要按鈕固定位置，但不應因 Footer 太高而讓主內容捲動區接近 0；小高度視窗縮減非必要頂部元素。
- 長 Prompt `Textarea` 可動態增高到合理上限，不把整頁變成無法操作的表單。
- Skeleton／Loading 區應保持佈局穩定，避免選單載入時跳動。
- 無障礙：可鍵盤開啟／收合 Provider、切 Tabs、進入字幕編輯；焦點回復原觸發按鈕；錯誤使用文字而非單靠顏色。

## 18. 安全、成本與模型資料

### 18.1 Provider 動態模型清單

- 模型列表與可用能力由 Native Host / Pi 或 Provider 的實際查詢提供；優先採**可驗證、可刷新的動態清單**。
- 支援手動 `重新整理模型`；呈現載入中、更新時間、載入失敗及快取過期狀態。
- Pi / SDK 的「已知模型清單」與「目前帳號可呼叫模型」不是同義詞，應區分顯示。
- 目前選中模型若不再可用，標記不可用並要求使用者重新選擇；**不得在背景任務中靜默改模型**。
- 本地模型（如透過本機工具提供）只有在相應 Host／Provider 真正可用、可列舉時才顯示；避免 UI 把尚未連接的服務當已連接。

### 18.2 價格資料

- 價格應有獨立資料來源、抓取時間、貨幣與 token 單位、模型版本、輸入／輸出及 cached token（若適用）等欄位。
- 可以將經整理的 public pricing metadata 置於可更新遠端資料源並在插件本地快取，**避免 Chrome Web Store 發布後價格被寫死**。
- 若使用第三方價格彙整資料，需遵守來源授權及更新頻率限制；當前無可信資料就不顯示確切金額。
- Cache 失效策略採 TTL + 明確刷新；可顯示「最後更新時間」與「價格僅供參考」。
- 這是**價格 metadata** 的更新機制，不代表透過 App 開發者的 API 代呼叫模型，也不表示開發者必須支付使用者每次的 API 費用。

### 18.3 連線與隱私

- 清楚告知使用者：哪些字幕、Prompt、影片 metadata 會送往所選 AI 提供者；何時需要授權或額外付費。
- 不在例外訊息／log／Crash report／同步設定中保存 API Key 或授權 token。
- Native Host 命令須驗證來源、限制允許操作、避免任意命令字串直接拼接 shell。
- Google Drive 僅用最小必要權限；連線失效、使用者撤銷存取時正確更新 UI。
- 外部模型生成的 Markdown 在閱讀器做 sanitization，外部連結需採安全導覽。
